# 02 · 产品需求（PRD）

本文把用户提出的 11 条诉求展开为**角色画像 → 功能需求（FR）→ 非功能需求（NFR）→ 关键用户故事**。

---

## 1. 角色画像（Personas）

| 角色 | 关注点 | 典型动作 |
|---|---|---|
| **平台管理员 (Platform/Super Admin)** | 全局合规、模型与厂商接入、配额与成本、安全策略 | 接入 LLM provider、设组织级默认 Agent/MCP/Skill、定权限策略、看全局审计与计量、Skill 安全评估终审 |
| **业务组管理员 (Group Admin)** | 本业务组内的资源与人员 | 在组织默认之上增删本组 Agent/MCP/Skill、管理组内项目、组级用量 |
| **项目管理员 (Project Admin)** | 单项目交付与协作 | 配置项目 Agent/工具/Skill、邀请成员、设项目级权限与沙箱画像、看项目运行与审计 |
| **开发者/成员 (Member)** | 用 Agent 干活、写自己的 Skill | 选 Agent 发起任务、看实时事件流、改写文件/跑命令、创作并发布 Skill |
| **审计员/安全 (Auditor/Security)** | 只读合规、安全评估 | 看审计日志与事件回放、参与 Skill 人工安审、配安全规则 |
| **自动化/集成方 (Service Account)** | 程序化调用 | 用 API/SDK 在 CI、定时任务、外部系统中发起 Agent Run 并消费 SSE |

> 同一自然人可在不同业务组/项目持有不同角色（多重成员关系）。

## 2. 功能需求（FR）

### FR-1 多 LLM（需求 1）
- FR-1.1 平台集中接入多家 LLM provider（Anthropic/OpenAI/Gemini/Bedrock/Vertex/Azure/国产模型/自建 vLLM 等），复用 `pi-ai` 的统一抽象。
- FR-1.2 管理员可在 **组织/业务组/项目** 级设置可用模型白名单与默认模型；下级可在允许范围内细化，被"锁定"的不可覆盖。
- FR-1.3 运行中可切换模型（RPC `set_model/cycle_model`）；切换受白名单校验。
- FR-1.4 **每个自然人向平台申请自己的 API Key**（平台签发，非 provider 裸 key）。用户用自己的 key 发起 LLM 调用，经内部 LLM Gateway 鉴权后代理到 provider。调用链路可追溯到具体自然人，满足审计归因需求。
- FR-1.5 provider 裸 key 由平台管理员在 LLM Gateway 集中配置，普通用户不可见、不可获取。
- FR-1.6 记录每次模型调用的 token / 成本 / 时延，关联到具体用户 key，进入计量与可观测。
- FR-1.7 用户 key 可在**任意第三方 CLI/工具**中使用（如 Claude Code、Codex CLI、Continue 等）。LLM Gateway 对外暴露 **OpenAI 兼容 API**（`/v1/chat/completions`）与 Anthropic 兼容 API（`/v1/messages`），第三方客户端只需将 `base_url` 指向 Polaris Gateway 并配置用户自己的 API Key 即可使用。所有调用仍经 LLM Gateway 鉴权、审计、计量——用户无需感知 provider 裸 key，企业不丢审计覆盖。

### FR-2 Sub-agent（需求 2）
- FR-2.1 Agent 可派生子 Agent（复用 `pi-subagents`），子 Agent 拥有**独立上下文窗口**。
- FR-2.2 子 Agent 的工具/Skill/MCP 集合与权限画像默认收窄（默认只读），由父 Agent 或定义约束，**不可超过父的有效权限集**。
- FR-2.3 支持并行子 Agent、深度与扇出上限、超时与中止、成本配额。
- FR-2.4 子 Agent 事件带 `parentSessionId/subagentId`，可在树视图中观测，结果作为工具结果回灌父 Agent。

### FR-3 MCP 与 Skill（需求 3）
- FR-3.1 平台经 `pi-mcp-adapter` **接入并治理** MCP：支持 stdio/HTTP MCP server，自动发现其工具并暴露给 Agent；支持 OAuth/Bearer 鉴权。
- FR-3.2 MCP server 在沙箱内以 sidecar 运行，能力受清单约束；**破坏性 MCP 工具默认强制审批**。
- FR-3.3 Skill 直接复用 pi 原生的 **Agent Skills 标准**（`SKILL.md`，YAML frontmatter + Markdown 指令；多目录发现、渐进式披露——启动只注入名称+描述，模型按需 `read` 全文；`/skill:name` 强制触发）。pi 内核已提供完整的 Skill 解析与运行时，无需自建 Skill 引擎。
- FR-3.4 中央 Skill 库按可见域挂载进沙箱（pi 原生只识别本地目录，平台在沙箱创建时将中央库中授权 Skill 以只读卷注入）。
- FR-3.5 Skill/MCP 均为带版本的目录资源，可被 Agent 定义引用。

### FR-4 完整页面管理（需求 4）
Web 控制台覆盖**全部功能**，信息架构（详见 [09](./09-api-clients-and-data-model.md)）至少包含：
- FR-4.1 工作台/对话：发起任务、实时事件流、文件树与 Diff、终端输出、人工审批弹窗。
- FR-4.2 Agent 管理：定义的增删改查、版本、发布可见域、试运行。
- FR-4.3 模型管理：provider 接入、provider 裸 key 配置（仅管理员可见）、模型白名单、默认模型、成本看板。
- FR-4.4 MCP 管理：server 接入与健康、工具清单、能力清单、审批。
- FR-4.5 Skill 市场与管理：浏览/搜索、创作、版本、**发布与安全评估工作流**、撤销/熔断。
- FR-4.6 运行与可观测：运行列表、事件回放、会话树、沙箱资源、日志检索。
- FR-4.7 组织/业务组/项目管理：层级、成员、邀请。
- FR-4.8 权限与角色：角色定义、权限矩阵、策略规则、可见域与锁定。
- FR-4.9 审计与合规：审计日志检索与导出、安全告警。
- FR-4.10 计量与配额：用量、成本、配额、预算告警。
- FR-4.11 **个人 API Key 管理**：每个自然人查看自己的 Key 列表、创建新 Key、设置过期时间/用途标签、撤销/轮转；Key 明文仅在创建时展示一次（`sk-...` 格式），后续不可再次查看。管理员可查看组织内所有 Key 的元数据（创建者、用途、创建/过期时间、最近使用时间），但不可查看 Key 明文。
- FR-4.12 设置：SSO/SCIM、出网白名单、沙箱画像、品牌化、通知偏好。

### FR-5 用户权限体系（需求 5）
- FR-5.1 四级作用域：**组织 → 业务组 → 项目 → 用户/Agent**。
- FR-5.2 内置角色（Super/Org/Group/Project Admin、Member、Auditor）+ 自定义角色；角色按作用域授予。
- FR-5.3 权限 = 动作（create/read/update/delete/use/run/publish/approve/manage）× 资源类型（agent/skill/mcp/model/sandbox/session/user/role/secret/policy/audit）。
- FR-5.4 资源**可见域继承**（上级默认流向下级）+ **托管锁定**（不可覆盖）+ 冲突裁决（显式 deny 优先、更具体作用域优先除非被锁定）。
- FR-5.5 运行时**工具级策略** allow/deny/ask（前缀/模式匹配），在 pi `tool_call` 闸门强制。
- FR-5.6 SSO（SAML/OIDC）登录、SCIM 自动开通/回收、可选桌面端 MDM 强制。
- FR-5.7 管理员可配置注册管控策略：**开放注册**（任何人均可注册）/ **关闭注册**（仅管理员手动创建或 SCIM 同步）；**注册白名单**——支持按邮箱域名（如 `@corp.com`）或精确邮箱地址白名单，仅白名单内的用户可注册或被邀请加入；白名单变更即时生效，不影响已注册用户。

### FR-6 统一治理 + 用户 Skill + 安全评估（需求 6）
- FR-6.1 管理员/项目管理员可统一管理"默认" Agent/MCP/Skill，下发到对应作用域。
- FR-6.2 用户可在私有作用域自由创作 Skill 并在自己的 Agent 中即用（仍受沙箱约束）。
- FR-6.3 用户把 Skill 发布到 项目/业务组/组织 时，**必须通过安全评估流水线**：草稿 → 提交 → 自动扫描（静态分析 + 能力清单核对 + LLM 风险判定）→ 命中则人工复审 → 批准@版本 → 按域发布 → 可撤销/熔断。
- FR-6.4 已批准 Skill **版本不可变**；管理员按版本白名单；撤销/熔断实时传播到运行中的 Agent。
- FR-6.5 发布/批准/授予/撤销/使用全程产生审计事件。

### FR-7 不只是聊天机器人（需求 7）
- FR-7.1 Agent 能在沙箱中真正执行：读写编辑文件、跑命令、调用 MCP 工具、加载 Skill、多步任务、子 Agent。
- FR-7.2 支持触发方式：交互式对话、API/SDK 程序化、定时（cron）、事件触发（如 Git/CI/webhook）。
- FR-7.3 任务可长时运行、可中止、可续跑、可分支重跑（会话树）。
- FR-7.4 产出物（文件变更/Diff/构建产物/报告）可查看、下载、回写到目标（Git PR 等，作为受审批的集成）。

### FR-8 独立沙箱（需求 8）
- FR-8.1 **一个 Agent 运行 = 一个隔离沙箱**：独立文件系统工作区、独立进程、资源配额（CPU/内存/磁盘/墙钟）。
- FR-8.2 出网**默认拒绝 + 白名单**（经出网代理）；FS 写限定工作区。
- FR-8.3 沙箱画像（镜像、预装工具、配额、网络策略）可由管理员按作用域定义。
- FR-8.4 沙箱生命周期可观测（创建/执行/超限/销毁），到期/超配自动回收。
- FR-8.5 密钥经间接引用注入沙箱，不经客户端、不落会话明文。

### FR-9 SSE 全链路可观测（需求 9）
- FR-9.1 一条 append-only 事件流为唯一事实源；SSE 为实时投影；headless JSONL 与之等价。
- FR-9.2 统一事件分类覆盖 session/turn/message/model/tool_call/mcp/subagent/skill/sandbox/permission/security/audit。
- FR-9.3 事件带作用域标签 + RBAC 过滤订阅 + 发射即脱敏；支持 `Last-Event-ID` 断点续传与历史回放。
- FR-9.4 三类消费者：实时 UI、审计+计量、安全监控。

### FR-10 企业统一管理 / 项目-业务组共享（需求 10）
- FR-10.1 同一项目/业务组成员**零重复配置**即可使用既有 Agent/模型/MCP/Skill。
- FR-10.2 不依赖本地环境：算力、工具、密钥、Skill 都在云端；客户端是瘦客户端。
- FR-10.3 资源在层级间可继承、可覆盖（除非锁定）、可下发默认。

### FR-11 多端接入（需求 11）
- FR-11.1 公开 **REST + SSE API**（OpenAPI 规范）+ 服务账号鉴权。
- FR-11.2 官方 **SDK**（TypeScript / Python）封装 API。
- FR-11.3 **CLI** 瘦客户端（登录组织云、发起/流式/管理资源）。
- FR-11.4 **桌面端**（Tauri/Electron）瘦客户端：对话+工作区+Diff+实时事件，可选"本地目录桥接"用于混合工作流。
- FR-11.5 Web 控制台（见 FR-4）。可扩展 IDE 插件、Slack/CI 集成。

## 4. 关键用户故事（节选）

1. **开发者零配置开工**：作为某项目成员，登录桌面端即看到项目已配好的 Agent 与模型，直接发起"修复这个 bug"任务，无需本地装环境或填 key——Agent 在云端沙箱里克隆仓库、跑测试、给出 Diff。
2. **管理员统一下发**：作为业务组管理员，我把一个"代码评审 Agent"+ 一组 MCP + 内部规范 Skill 设为本组默认，组内所有项目立即可用且版本一致。
3. **用户发布 Skill 经安审**：作为开发者，我写了个"按公司模板生成接口文档"的 Skill，提交发布到业务组；系统自动扫描（无危险 shell、出网仅限内网域名、能力清单匹配），低风险直接批准@v1，组内可见；若命中风险则转安全人工复审。
4. **安全熔断**：作为安全审计员，发现某已发布 Skill 的某版本有问题，一键撤销，运行中的 Agent 即时停用该 Skill 并产生审计事件。
5. **程序化集成**：作为 CI 服务账号，我用 SDK 在合并请求时发起 Agent Run 做安全审查，通过 SSE 实时获取进度，结果回写为 PR 评论。
6. **运行回放**：作为审计员，我对某次高风险运行做事件回放，逐步看到每个工具调用、审批决策、模型成本与子 Agent 派生。
7. **受控的破坏性操作**：作为开发者，Agent 试图执行 `rm -rf` 或调用破坏性 MCP 工具时，闸门拦截并向我（或值班审批人）弹出确认；拒绝则 Agent 走替代路径。
